# ICA closed-loop I x P confirmatory extension - frozen protocol v2

Frozen before confirmatory inference on 2026-10-31.

## Status of the original run

The earlier eight-task experiment is retained as a pilot. Its outcomes were already known before this protocol and therefore are not used to select or alter confirmatory tasks, models, interfaces, scores, thresholds, or primary comparisons.

## Confirmatory question

Does the behavioral effect of model-visible tool granularity replicate on a larger set of previously unseen tasks, while the scoring-partition effect remains separately identifiable?

## Confirmatory task cohort

Exactly 32 new deterministic register-workflow tasks, IDs T09-T40.

Tasks are generated before inference from the same eight operation-pair template classes used by the pilot, cycling through those classes four times. Concrete initial states, registers, operation arguments, and target states are generated by Python random.Random with frozen seed 310267.

No confirmatory task is selected, removed, regenerated, or reordered based on model outcomes.

## Models

Exactly the same two public models used in the pilot:

1. koboldcpp/Qwen2.5-Coder-3B-Instruct
2. koboldcpp/llama-3.2-3b-instruct-q4_k_m

No model is added, removed, or replaced based on confirmatory outcomes.

## Interface factor I

Unchanged from the pilot.

I_fine exposes one primitive operation per call:
ADD, COPY, SET, SWAP.

I_macro exposes fixed two-operation composites:
ADD_COPY, COPY_ADD, SET_COPY, SWAP_ADD.

Every macro deterministically expands to two canonical primitive events. The macro interface intentionally changes the model-visible decision/observation granularity; its contrast with I_fine is therefore a behavioral interface effect, not a fixed-execution equivalence claim.

## Scoring factor P

Unchanged from the pilot.

Every realized trajectory is canonicalized to four primitive positions.

P_fine is mean exact positional primitive correctness over the four positions.

P_macro is the mean of two all-correct block labels for fixed blocks [1,2] and [3,4].

The pass/fail threshold is 0.5 and is frozen before confirmatory inference.

## Primary endpoint

Endpoint success: the final four-register state exactly matches the target final state.

## Primary confirmatory contrast

Macro-interface minus fine-interface endpoint success, averaged within each task across the two frozen models.

The independent sampling unit for inference is the task. Bootstrap resampling therefore samples task IDs and retains both models within each sampled task.

## Secondary contrasts

1. Macro-interface minus fine-interface P_fine.
2. Macro-interface minus fine-interface P_macro.
3. P_macro minus P_fine within I_fine.
4. P_macro minus P_fine within I_macro.
5. I x P difference-in-differences interaction.
6. Qwen-minus-Llama task-paired margins under each interface for endpoint success, P_fine, and P_macro.
7. Threshold-decision flip counts.

All secondary comparisons use task-cluster inference. A model-order reversal is reported as statistically established only if the corresponding task-cluster interval excludes zero in opposite directions under the two interfaces.

## Repetitions

One confirmatory episode per task/model/interface cell is primary. This yields 32 x 2 x 2 = 128 confirmatory episodes. The task, not episode, remains the inferential unit.

## Analysis

Report percentile task-cluster bootstrap 95% intervals with 10,000 resamples. For paired task-level contrasts, also report a seeded sign-flip randomization p-value as a sensitivity check.

The pilot and confirmatory cohorts must be labeled separately. Any pooled summary is descriptive and cannot replace the confirmatory analysis.

## Stopping and reporting rule

The full 32-task confirmatory cohort is run once under this frozen protocol. No task is added, removed, or rerun because of its effect on significance, ranking, or direction. Null, attenuated, or contradictory results are retained and reported.
